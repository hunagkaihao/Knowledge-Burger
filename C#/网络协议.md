# TCP Trasnmission and Control Protocol（传输和控制协议）

- **层级：** 位于 OSI 模型的**传输层**（第4层）。
- **作用：** 提供**可靠的、面向连接的**数据传输服务。它只负责把字节流（Byte Stream）准确无误地从一端送到另一端，保证数据不丢失、不乱序、不重复。
- **本质：** 它是通用的通信管道，**不关心传输的内容是什么**。你可以用它传网页、发邮件、传文件，也可以传工业数据。

# Modbus TCP

- **层级：** 位于 OSI 模型的**应用层**（第7层），运行在 TCP 之上。
- **作用：** 定义了**工业设备之间交换数据的具体格式和规则**。它规定了如何读取线圈状态、如何写入寄存器、数据帧的结构（MBAP头 + PDU）等。
- **本质：** 它是**基于 TCP 的特定应用协议**。没有 TCP，Modbus TCP 无法传输；但只有 TCP，设备之间无法理解工业数据。

# TCP vs UDP

|          | TCP                                                          | UDP                                                          |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 连接方式 | 面向连接。通信前必须通过“三次握手”建立连接，通信结束后通过“四次挥手“释放连接 | 无连接。发送数据前不需要建立连接，直接发送数据包             |
| 可靠性   | 可靠传输。提供确认机制、重传机制、流量控制和拥塞控制，确保数据按序、完整、不重复地到达接收方 | 不可靠传输。不保证数据是否到达、是否按序、是否重复。丢包或乱序由应用层处理 |
| 传输效率 | 开销较大。因为要维护连接状态、确认、重传等机制，传输效率相对较低，延迟较高 | 开销小、速度快。没有连接建立和确认机制，适合实时性要求高的应用 |
| 数据顺序 | 保证数据按发送顺序到达                                       | 不保证顺序，每个数据包独立路由                               |
| 头部大小 | 头部至少 20 字节（可变长，含选项字段）                       | 头部固定为 8 字节（源端口、目的端口、长度、校验和）          |
| 应用场景 | Web 浏览（HTTP/HTTPS)<br />文件传输（FTP)<br />邮件（SMTP、POP3、IMAP）<br />任何需要可靠性的场景 | 实时音频通话（如 Zoom、VoIP）<br />在线游戏<br />DNS查询<br />广播或多播通信<br />对延迟敏感、能容忍少量丢包的场景 |
